# PROJECT BRIEF — Im PPT Generator

> 작성일: 2026-07-03 · 상태: active

## 엘리베이터 피치

**발표 자료가 필요한 모든 사람**을 위해, **자료조사(출처 검증)부터 목차 설계, 슬라이드별 디자인 계획 보고/승인, 실시간 생성, 수동 편집, PPTX 다운로드까지** 전 과정을 수행하는 **End-to-End AI 프레젠테이션 에이전트**입니다.
기존 Gamma/Genspark류와 달리 **① 슬라이드 한 장 한 장을 만들기 전에 계획을 보고하고 허락받는 페이지 단위 HITL**, **② 모든 수치·주장의 출처를 구조적으로 관리하는 할루시네이션 제로 파이프라인**이 있습니다.

## 문제 정의

### 현재 상황 (As-Is)
- PPT 제작은 자료조사 → 구조 설계 → 콘텐츠 작성 → 디자인 → 검토의 다단계 노동이며, 실무자 기준 덱 하나에 수 시간~수 일이 소요된다.
- 기존 AI PPT 도구(Gamma, Genspark, Canva 등)는 "한 번에 전부 생성" 모델이라, 결과물이 의도와 다르면 **전체 재생성**하거나 처음부터 수동 편집해야 한다.
- AI가 넣은 수치/주장의 출처가 불명확해 업무·발표용으로 그대로 쓰기 불안하다 (Manus조차 인용 미표기가 공식 약점).

### Pain Point
1. **통제 불가**: 생성 과정이 블랙박스 — 목차 승인 이후에는 개입 지점이 없다.
2. **신뢰 불가**: 통계·인용의 출처 추적이 안 되어 팩트체크를 사람이 다시 해야 한다.
3. **수정 비용**: 특정 페이지만 고치고 싶어도 도구가 페이지 단위 컨텍스트를 못 잡는다.
4. **Export 배신**: 웹에서는 예쁜데 PPTX로 받으면 깨진다 (Gamma 고질, Tome은 이것 때문에 사망).

### 원하는 상태 (To-Be)
- 유저가 원하는 만큼 개입(자율도 L0 전자동 ~ L3 페이지별 승인)하면서 AI가 덱을 만든다.
- 모든 팩트는 소스로 역추적 가능하고, 유저가 승인한 팩트만 슬라이드에 들어간다.
- AI가 슬라이드를 그리는 과정이 실시간으로 보이고, 완성 후엔 페이지를 골라 AI 수정 또는 직접 수동 편집한다.
- 다운로드한 PPTX가 PowerPoint에서 그대로 편집 가능하다.

## 기획 의도 — 왜?

| 질문 | 답 |
|---|---|
| **왜 이 문제?** | AI PPT는 검증된 수요(Gamma $100M ARR)이지만, 14개 제품 조사 결과 "과정 통제(HITL)"와 "출처 관리"는 전 제품이 비어 있는 공백이다 → [경쟁 분석](../01-research/COMPETITIVE_ANALYSIS.md) |
| **왜 이 방식?** | JSON 스키마 SSOT + 듀얼 렌더러가 "수동 편집 + 페이지 단위 AI 수정 + 편집 가능 PPTX"를 동시에 만족하는 유일한 구조 → [ADR-001](../02-architecture/ADR-001-json-schema-ssot.md) |
| **왜 지금?** | ① LLM 구조화 출력(스키마 강제)이 성숙 ② 오픈소스 스켈레톤(Presenton 8.7k★)이 검증됨 ③ Tome 사망(2025-04)으로 "export 충실도" 교훈이 명확해짐 |

## 타겟 사용자

- **1차**: 회사 보고/제안/IR 덱을 만드는 실무자 — 출처와 통제가 중요한 고부담 덱
- **2차**: 강의/발표 자료를 만드는 교육자·학생
- **3차**: API/셀프호스트로 슬라이드 생성을 내장하려는 개발자 (v2)

## 차별화 포인트 (3개)

1. **페이지 단위 계획 승인 게이트** — 슬라이드마다 "이 페이지는 이런 디자인·내용으로 만들겠다"를 보고 → 승인 후 생성. **14개 경쟁 제품 중 어디에도 없음.**
2. **인용의 구조적 관리** — 소스→팩트→승인→슬라이드 요소 `citationId`까지 역추적 체인. 경쟁 제품은 인용 "삽입"만 있고 "관리"가 없음.
3. **Export 충실도 우선 설계** — 스키마로 요소를 제한해 PptxGenJS 매핑이 항상 성립. "웹에서 보이는 것 = PPTX에서 편집되는 것".

## SWOT

| Strengths | Weaknesses |
|---|---|
| HITL·출처 관리 시장 공백 선점 | 템플릿 커버리지를 직접 쌓아야 함(디자인 품질은 축적 게임) |
| 스키마 SSOT로 export 충실도 구조적 보장 | 1인 개발 — 속도 제약 |
| 검증된 레퍼런스 구조(3프로젝트) 재사용 | 이미지 생성 단가(덱당 $1~2) 관리 필요 |

| Opportunities | Threats |
|---|---|
| Tome 사망 이후 "PPTX 왕복" 수요 명확 | Gamma/Genspark의 빠른 기능 추가 |
| API/MCP 신흥표준 — 개발자 시장 초기 | LLM 가격/정책 변동 |
| 셀프호스트 수요(규제 산업) — Presenton 단독 영역 | 검색 API 종속(Tavily 인수 등 변동) |

## 성공 기준

- **MVP(P1)**: 프롬프트 → 아웃라인 승인 → 템플릿 기반 생성 → 웹 렌더 → **PowerPoint에서 편집 가능한 PPTX** 다운로드가 실 API로 관통
- **v0.5(P4)**: 3게이트 HITL + 실시간 생성 스트리밍 + 페이지 단위 AI 수정 — 핵심 차별화 완성
